# Tessera-small 对齐记录

## 当前实现（2026-11-25）

单张、批量、渐进预览和局部重绘使用同一个模型采样器。CPU 保持 SIMD 路径。Auto 和严格 Vulkan 在 M3 Max 上把 CLIP、去噪器、CFG、颜色过滤和选择、空间 NMS、提交以及 polish 重掩码放到设备。主机负责分词、与 PyTorch CPU 相同顺序的随机数、批次及步调度、RGBA 输出。每步读回提交状态；开启自条件时也会回传下一步使用的概率。无驱动时，Auto 实际以 CPU 完成推理，指定 Vulkan 会在计算前报错。[分组件数值与设备记录](device.md)

九档权重的默认 16 步均以作者的同权重 PyTorch 作参考。每档各跑 CPU、Auto、严格 Vulkan，每组分别运行两个独立 CLI 进程和同一 HTTP 服务上的两次请求。各组四张图像素一致。最终任务指标和 ERNIE-Image、P-JiT 的真实权重回归列于[默认采样矩阵](full_steps.md)。

四步 greedy 使用 CFG 3，颜色和位置选择温度均为 0。下表给出每 256 个像素中与同权重官方参考一致的个数。每行的 CLI 和 HTTP 都逐像素相同。四个掩码像素的单步重绘在 27 个组合下均与官方一致，含原样保留的 252 个像素。后者每次执行 60 个去噪投影，Auto 和严格 Vulkan 均全部在 GPU 执行。

F32、seed 17、每批两张，分别测试重复提示词和不同提示词，四步 decode 后再 polish 一步。三种后端的 60 张预览和 12 张最终图均与官方的对应图完全一致。逐张核对了 HTTP SSE 顺序、阶段、索引、结束事件和非流式结果，重复提示词还逐字节对照了 CLI 文件。真实服务在 SSE 运行时对非法批量返回 400、对并发生成返回 429，断开客户端后的下一次生成成功。极大有限 guidance 引起非有限 logits 时，服务发出 error 事件。[复现脚本](batch.py)

已用 Z-Image Turbo Q8_0 的原始 CLI、HTTP 请求复测公共图像入口，64×64 单步 PNG 与初版基线的 SHA256 相同。默认库测试的 24 项失败与改动前逐项相同。下文保留初版的设备分工及入口重构证据，当前设备分工与输出以本节链接的记录为准。

### 同机耗时

固定 F16、seed 0、8 线程、16 步、单图，各测三次。Rust CLI 的墙钟中位数为 CPU 4.475 秒、Auto 3.065 秒、严格 Vulkan 3.085 秒，包含进程启动、加载、采样和 PNG 输出。官方 PyTorch CPU 在载入同权重后进行分词、CLIP 编码、采样和转图，中位数为 15.686 秒。初版混合 Vulkan CLI 的同样例单次耗时为 7.61 秒。当前实现把同一前向的设备算子录入同一个命令缓冲区，减少了各层之间的主机往返。[三次原始计时](performance.json) · [复测脚本](performance.py)

## 初版适配（2026-11-24）

2026-11-24，在 Apple M3 Max（ARM64 NEON、MoltenVK 1.4.2）上验证作者发布的 Tessera-small。标准输入是 `golden crown with blue gems`，批量大小为 1。独立参考直接运行固定 revision 的作者代码，并用 gguf-py 反量化相应 GGUF 替换权重。F32 导出的 CLIP 隐状态、两个 CFG 分支的 logits 和四步 greedy 结果，与直接加载原始文件的参考输出一致。[环境和复现命令](README.md)

## CPU、Auto 和 Vulkan

每行均实际运行 CLI 和 `POST /v1/images/generations`。分词 ID、形状及 PNG 尺寸和 RGBA 通道数作精确检查。CLIP 指标取 24×512 隐状态和 512 维 pooled 中较大的相对 RMSE。logits 指标取第一步全 mask 和第二步部分 mask（含上一步自条件概率）各自的 cond、uncond 四个完整张量中较大的绝对 RMSE、较小的 cosine。每张 logits 有 256×512 个元素。

四步生成使用 CFG 3、颜色和位置选择温度均为 0。CLI/HTTP 两列耗时以秒计，CLI 含启动及加载，HTTP 从已启动服务发出请求起算。两条入口在每一行都产生完全相同的 256 个 RGBA 像素；“同档参考”列是与同权重 PyTorch 的四步成图相同的像素数。由于提交顺序依赖置信度，接近的分数可以在后续步生成不同颜色。

CLIP 的验收阈值（相对 RMSE 上限 / cosine 下限）为 F32 `0.0005 / 0.999999`、F16 和 BF16 `0.025 / 0.9995`、块量化 `0.075 / 0.997`。去噪 logits 的阈值（绝对 RMSE 上限 / cosine 下限）为浮点权重 `0.005 / 0.9999`、块量化 `0.15 / 0.995`。上述 27 组的 CLIP、共 108 张 logits 均通过。四步最终离散图另行报告像素差异。不同 prompt、seed、设备和驱动的分数可能不同。

设备计数来自实际投影。每次 CLIP 编码有 48 个投影组，CPU / Auto / Vulkan 三种策略分别有 0 / 12 / 48 组在设备上完成。四个去噪检查点的 230 次投影中分别有 0 / 208 / 230 次在设备上完成。严格 Vulkan 下所有线性投影在 GPU 上，CLIP attention、归一化、逐通道卷积、采样和 PNG 编码仍含主机计算。权重依张量保留原生格式参与投影，宿主侧中间状态为 F32。模型对全画布双向重算，无自回归 KV cache 或 JEV 接口。隐藏 Vulkan 驱动后，F16 Auto 回退 CPU 并成功生成，严格 Vulkan 在加载前返回设备不可用。

## 默认 16 步耗时

同机同一 F16 GGUF、8 个 CPU 线程、一个提示词、CFG 3、seed 0。Rust CPU CLI 用时 4.52 秒，严格 Vulkan CLI 用时 7.61 秒，均含进程启动、加载和 PNG 写入。官方 PyTorch CPU 在载入相同反量化权重后，文本编码、16 步生成和转图用时 16.12 秒。两个 Rust 输出各有 256/256 像素与本档 PyTorch 相同。这是该样例的单次墙钟时间。Vulkan 对 16×16 的小画布执行了 1,840 次去噪线性投影，期间仍须为主机上的归一化、卷积、采样等操作往返设备。

## 默认采样、局部重绘和回归

- 默认 16 步、seed 0，F32 CPU 与官方随机采样生成的 RGBA 图完全一致（256/256）。Rust 使用 PyTorch CPU 的指数竞争和 Gumbel 采样次序。
- 在 `red apple with a leaf` 上，6 步温度退火、top-k/top-p/min-p、cosine CFG 和提前提交的组合与官方一致（256/256）。同一提示下用部分已知画布、linear CFG、关闭 NMS 和自条件、两步 polish 再验，也为 256/256。
- 另外对上述全部 27 个“精度 × 后端”组合，逐项通过 CLI 和 HTTP 对同一画布做局部重绘。每组两个入口都与本档 PyTorch 一致，均保留 252/252 个已知像素、重绘 4/4 个指定像素。一次去噪的 60 次投影在 CPU / Auto / Vulkan 策略下分别有 0 / 53 / 60 次实际在设备上执行。
- 在 `an emerald shield with golden trim` 上，通过 OKLab 映射任意 RGBA，覆盖透明度 127/128 的边界和不透明黑色。F32 CPU 在 5 步生成和 2 步 polish 后保留 156/156 个指定像素，100/100 个重绘像素与作者 `TesseraPipeline.inpaint` 相同。[复现脚本](inpaint.py)
- 自审修复了空提示词的传递，以及无 `shaderFloat64` 设备初始化公共投影时误编译 PiVo 专用 attention 的问题。旧版的共享 Vulkan 投影测试在 M3 Max 复现 shader 初始化失败，修复后 11 种格式的共享 batched-linear 设备测试及 PiVo 能力门禁测试通过。实跑 PiVo F32 的 CPU 和 Auto WAV 都是 29,920 个样本，SHA256 均为 `416a79b0a166ac750ff39cdb81ebb11b38a558ed7b98c8f4e0ddd4fd97a83bc8`。该机器无法验证需要 FP64 的 PiVo shader。
- `cargo test --locked --lib` 在上游基线为 1691 passed / 24 failed / 119 ignored，首次适配提交 `517fbfdf6` 为 1698 passed / 24 failed / 121 ignored。逐名比对 24 个失败完全一致。新增两项 ignored 是需要真实文件的 CLIP 与去噪 oracle，已在上表逐格执行。Cargo 元数据中的 9 个二进制名称、路径与基线一致。

真实权重的中间值验证可按下列命令复现，`TESSERA_COMPUTE` 可选 `cpu`、`auto` 或 `vulkan`。

```sh
fmt=f16
export TESSERA_GGUF="$ASSETS/tessera-small-$fmt.gguf"
export TESSERA_FIXTURE_DIR="$ASSETS/parity/$fmt"
export TESSERA_COMPUTE=vulkan
cargo test --locked --profile release-fast --features vulkan --lib tessera_clip_oracle -- --ignored --nocapture
cargo test --locked --profile release-fast --features vulkan --lib tessera_denoiser_oracle -- --ignored --nocapture
```

## 2026-11-25 图像生成入口回归

以 PR 提交 `517fbfdf6` 的二进制为基线，在同一台 Apple M3 Max 上对照合入公共 diffusion 入口后的 CLI 和 HTTP。F16 CPU、8 线程、seed 0，四步随机生成、四步 greedy 和单步重绘三个样例的两条入口都和重构前产生相同的 PNG 字节。三张图分别包含 92、122、96 个透明像素。F32 HTTP 的空提示返回 200，错误尺寸返回 400，缺少提示字段返回 422。

复跑九档 GGUF × 三种计算策略的生成、重绘矩阵，两条入口共 108 张 PNG，与重构前逐文件比对，108 对字节一致。全量库测试为 1699 passed / 24 failed / 121 ignored，失败名单与基线一致。

另用 Z-Image Turbo Q8_0、Qwen3-4B Q8_0 和 F16 VAE 验证已有 RGB 路径。CPU、8 线程、64×64、1 步、seed 42，前后两版的 CLI 和 HTTP 输出共四张图，PNG SHA256 均为 `2be759c21a6be8bee1f7aea790c487781605b3d8bd15666214179d0cc1cefabb`。四类无效请求的 HTTP 状态与错误正文也相同。后续取得 ERNIE-Image 和 P-JiT 的完整组件，并复跑了两种模型的真实 CLI 和 HTTP。[回归结果](full_steps.md)
