# Tessera-small 设备执行与数值对齐

## Resident CLIP text encoder

在 Apple M3 Max（Vulkan / MoltenVK，支持 int8 dot product 和 shader f16）上，用提示词 `golden crown with blue gems` 实测九种 GGUF 精度和三种计算策略。Oracle 将各 GGUF 的权重独立解码为 F32，加载到固定版本的官方 PyTorch 文本塔。比较全部 24 × 512 个隐藏态（states）和第一个 EOS 处的 512 维向量（pooled）。分词得到的 24 个整数 ID 要求完全相同，浮点结果使用相对 RMSE 与余弦相似度。

`cpu` 走 SIMD 投影与 CPU attention；九个精度的 CPU 误差统计与引入设备图之前相同。`auto` 和 `vulkan` 在本机都完成了一次 CLIP 计算提交：一次 embedding 合成、72 次原精度权重投影、25 次 affine LayerNorm、12 次因果 attention、12 次 QuickGELU 和 24 次 residual。主机按 token ID 拷贝 24 行原编码 GGUF 权重，设备完成解码和全部数值前向，最后回读 49,152 字节。这里的提交数只统计该次前向 compute command buffer。首次权重上传、输入输出传输另计。

用 [参考模型与 fixture 命令](README.md) 准备 `ASSETS` 后，以下命令从仓库根重放矩阵。

```sh
for fmt in f32 f16 bf16 q8_0 q4_0 q4_1 q4_k q5_k q6_k; do
  for policy in cpu auto vulkan; do
    TESSERA_GGUF="$ASSETS/tessera-small-$fmt.gguf" TESSERA_FIXTURE_DIR="$ASSETS/parity/$fmt" \
      TESSERA_COMPUTE="$policy" RMI_COMPUTE_TRACE=1 cargo test --locked --profile release-fast \
      --features vulkan --lib tessera_clip_oracle -- --ignored --nocapture || exit 1
  done
done
```

提示词缓存复用回归 `tessera_clip_reuses_device_across_prompts` 在同一编码器依次运行 crown → apple → crown。F32 与 Q4_K 均通过，第三次前向复现第一次的隐藏态及 pooled 向量，第二次输出通过独立 CPU 前向对照。

共用 online attention 在相同物理设备上复跑现有的 partial tile、causal/non-causal mask 与内存门槛回归，两个测试均通过。两个 mask 模式对 CPU 的最大绝对误差均为 3.58 × 10⁻⁷。另用现有 P-JiT Q4_0 和 Qwen3.5-4B Q4_0 权重走 Vulkan CLI（提示词 `A red cube on a white table.`、64 × 64、一步、seed 42、8 线程）。修改前后的 CLI 输出均完成 487 次设备计算提交，PNG SHA256 同为 `9baa179b91a0fdccba571ab1ef657ea25fe977d4898cb4c452f1b1c427253d25`。

## Vulkan sampler

用 F32 GGUF 和 `--compute vulkan` 运行提示词 `red apple with a leaf`，seed 123、6 步、CFG 2.5、温度 0.8，比较官方 PyTorch sampler 生成的最终 RGBA 像素。

| 采样参数 | 一致像素 | 实际设备投影数 |
|---|---:|---:|
| 温度终值 0.25、cosine CFG、top-k 64、top-p 0.8、min-p 0.08、commit threshold 0.85 | 256/256 | 690 |
| 温度终值 0.1、linear CFG、关闭 spatial NMS 与 self-conditioning、2 次 polish，保留透明及非透明像素 | 256/256 | 906 |

第二组的画布索引 `i` 从零起算：`i % 3 == 0` 固定为透明 0，其余 `i % 7 == 0` 固定为颜色 146，剩余像素待生成。另测一步、温度 0、CFG 为 3.4028234 × 10³⁸ 时，CPU 和 Vulkan 均检测到 guided logits 溢出，CLI 以非零状态退出。

## Resident denoiser

2026-11-25 在同一台 Apple M3 Max 上，使用每个 GGUF 独立反量化后的官方 PyTorch 模型比较 256 × 512 个 logits。每种格式和计算策略都检查四个输出：全掩码画布上的有条件和无条件分支，以及使用相同的部分提交画布和上一轮概率做自条件输入时的两个分支。下面的 RMSE、最大绝对误差和余弦相似度取各自最差值。浮点门槛为 RMSE ≤ 0.005、cosine ≥ 0.9999，块量化门槛为 RMSE ≤ 0.15、cosine ≥ 0.995。共通过 108 个完整张量检查。

|---|---:|---:|---:|---:|---:|---:|
| F32 | 0.000004 | 0.000004 | 0.000004 | 0.000024 | 1.00000000 | 626 |
| F16 | 0.001076 | 0.001061 | 0.001061 | 0.004782 | 0.99999999 | 626 |
| BF16 | 0.000005 | 0.000007 | 0.000007 | 0.000030 | 1.00000000 | 626 |
| Q8_0 | 0.031334 | 0.031296 | 0.031296 | 0.171128 | 0.99998858 | 850 |
| Q4_0 | 0.031851 | 0.031127 | 0.031127 | 0.173021 | 0.99998784 | 850 |
| Q4_1 | 0.032845 | 0.033193 | 0.033193 | 0.210392 | 0.99998788 | 850 |

每个 GPU 前向一次计算提交，张量留在设备上穿过全部 2+8+2 层。设备执行掩码比例与 Fourier 特征、条件和自条件投影、RMSNorm、调制、Q/K 旋转、8 头双向 attention、3×3 逐通道卷积、SwiGLU、2×2 合并/展开、残差与输出 head。矩阵保留 GGUF 原生权重格式。GPU 测试记录到 230 次投影，其中两次用于初始化颜色嵌入，余下 228 次分布在四次前向中。表内 dispatches 按四次前向计，排除了初始化；块量化增加了激活量化 dispatch。

直接比较 logits 的测试中，四次前向均为 4 次计算提交，共向设备写入 1,257,472 字节、回读 2,097,152 字节（四个完整 logits）。真实采样将条件分支、CFG 与调色板采样一起录入命令缓冲区，按需回读自条件概率和采样结果。CPU 保留 PyTorch 顺序的 MT 随机数/批次调度、回调和最终 PNG 编码。Strict Vulkan 报告设备错误，Auto 可从保留的主机输入和相同随机数重算失败的采样步骤。

用 `TESSERA_GGUF` 指向对应文件、`TESSERA_FIXTURE_DIR` 指向同一精度的 PyTorch fixtures，分别设置 `TESSERA_COMPUTE=cpu`、`auto`、`vulkan` 运行：

```sh
cargo test --locked --features vulkan --profile release-fast --lib tessera_denoiser_oracle -- --ignored --nocapture
```
