# Timestral F32 GPU 优化

Timestral 的投影改用仓库已有的 F32 分块矩阵乘法。模型文件、F32 激活/权重和数值验收阈值均保持原样。GPU 上传时把矩阵存储转为 `[input, output]`，重排复用现有 Rayon 线程池；GPU arena 增长时仍按原逻辑重新上传。每层的 flush 限制保留，没有修改 shader 或引入依赖。

## 定位依据

NAVI31 上使用临时插桩，在每个算子后提交并等待，以同步墙钟时间分组。这些诊断包含额外提交开销，不是 GPU timestamp 或无扰动的逐 kernel 时间线。标准输入两次常驻诊断的矩阵乘法分别为 844.2 / 842.3 ms，占诊断阶段约 96%；4096 点输入为 5639.8 / 5645.1 ms，占约 98%。原 F32 路径每个 64 线程工作组只有一个线程做完整标量归约。

分块内核复用 F32 FMA，不将激活或权重转为 F16/BF16。其归约结果按原有混合绝对/相对误差界验收。权重重排按原始位模式检查，并覆盖不完整分块及非法 shape；GPU 算子检查覆盖 1/5/33 行、130 输入维、65 输出维、输入/输出 padding，并与独立 F64 参考比较。

## 同机 A/B

硬件仍为 RADV NAVI31 / gfx1100、48 GiB 显存，16 核配额的 EPYC 9334；Rust 1.98.1，完整 release/fat LTO/native CPU，无 parity-trace，4 个 CPU 线程。原始版本与优化版在同一机器使用相同模型和输入。最终推理源文件 SHA 与本地一致，GGUF SHA 为 `7628bcbfe43c8fec82bfbeace0ebbeb7dcd49facec6a785a51f430995d704e10`。

常驻计时包括完整预测、CPU 前后处理与 GPU 同步读回；完整 CLI 计入进程启动至退出，保留系统/驱动缓存。主矩阵每次先执行一次首次预测，再重复 3 次常驻预测，另启动 2 次 CLI；最大上下文仅重复 1 次、CLI 1 次。短输入和标准输入另各补 5 次交替 CLI，表中使用全部 7 次的中位数。共 89 个进程测量、155 次预测，不含被丢弃的受干扰尝试和中间顺序重排版本。基线同时测 CPU/Vulkan；最终版本测 Vulkan，CPU 实现未改，输出与同输入的基线 CPU/GPU 都比较。

短输入完整 CLI 仍有回退，标准输入的常驻 GPU 也仍略慢于四线程 CPU。本机短请求/单变量 512 点输入建议显式使用 `--compute cpu`；长上下文、多变量和常驻长预测更适合 GPU。Auto 仍按原策略选择 GPU。完整 CLI 存在波动：标准优化版样本范围约 1.07–3.20 s，短输入约 0.91–3.73 s，所有样本均保留，未删除无已知任务重叠的慢样本。

每次测量前等待 3 秒无已知编译/推理任务；测量中检查 Rust/C++ 编译器及已知 RMI/GPU probe 进程，出现重叠即重测。接受的测量均无此类采样重叠，但这不证明独占物理主机或 GPU；上传和其他不可见工作仍可能影响延迟。补采样保留了首次标准 CLI 的 3.20 s 偏高值。

八组最终预测与基线 CPU/GPU 均通过原有误差界；NAVI31 最差最终 NRMSE 为 `2.5752e-6`。每个后端的重复预测和对应 CLI 输出都精确一致。普通用例首次上传后保持 194 次上传，1025 步因 arena 增长为 387 次，随后不再重传。最终常驻进程峰值 RSS 最高约 887.9 MiB；设备峰值分配最高 820.9 MiB，与原分配策略一致，两者口径不同。

完整采样、二进制/源文件哈希、诊断分组及验收记录见 [gpu_optimization.json](gpu_optimization.json)。复现沿用 [README](README.md#性能复现) 的 release 构建和 benchmark 命令；使用 `--warm-repeats 3 --cli-repeats 2`，最大上下文使用 1/1。原实现使用 `efc1477` 的推理代码；远程基线从 `cc72a61` 构建，两者推理实现相同，前者仅增加性能测量工具。`--wait-idle` 默认只检查 Rust 编译器，重现本次隔离口径时还需检查 C++ 编译器及其他 GPU 客户端。补采样仅针对短/标准输入，以基线/优化版交替运行各 5 次。


## 数值与覆盖

最终代码在 M3 Max / MoltenVK 上对固定官方 CPU/F32 Oracle 运行 10 个用例 × Vulkan/Auto，共 20 次 GPU CLI、6,788 个检查点。模型 203 个 F32 张量的原始文件 payload、mask、position、检查点顺序/形状/次数仍精确检查；浮点路径仍使用 `max_abs <= 3e-5 + 3e-4 * max_abs(reference)` 和 `RMSE <= 3e-5 + 5e-5 * RMS(reference)`。

全部通过；最终预测最差 NRMSE 为 `2.9871e-6`。长 horizon 大幅值尾部的最大最终绝对误差为 `0.07275390625`，中间绝对误差最高 `3136`，相对界通过不表示绝对误差都小。Vulkan 与 Auto 的最终输出精确一致。并行重排与顺序重排的全部预测输出也精确一致。两次关闭运行时 trace 的普通 CLI 与插桩输出精确一致。完整记录见 [gpu_optimization_verification.json](gpu_optimization_verification.json)。

NAVI31 的无插桩 release 验证比较完整预测及 CLI；该设备未运行 Oracle 全部中间检查点。本轮未重复全库测试、官方数据集质量评测或并发服务吞吐测试。GPU 前后处理仍包含 CPU 缩放、patch/head 投影和输出折叠。
