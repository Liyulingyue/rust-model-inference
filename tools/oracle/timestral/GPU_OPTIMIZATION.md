# Timestral F32 GPU 优化

## 显存驻留与短批次投影（2026-10-23）

独显现在通过已有的 device-local 上传接口保存 F32 投影权重，中间激活使用已有的显存 arena 和显式 staging 读写；UMA 保留映射内存。输入上传在命令录制前完成，最终输出及 parity 检查点在提交完成后读回，避免 staging 操作重复获取命令锁。

此前的 32-token × 64-column 分块在短输入、768 个输出时只有 12 个工作组。新增 F32 小矩阵内核每组计算 4 个 token × 2 个输出列，32 个线程协作完成每个点积，使用 F32 FMA 和共享内存归约，不需要中间 scratch 或第二次归约 dispatch。仅在不超过 32 行、4096 输出列、单个 F32 投影时由算子内部选择；较大批次、BF16 和多输出分组仍使用原分块内核。单独的 768×768 GPU timestamp 探针中，4/19 行投影由约 0.23/0.29 ms 降至约 0.048/0.052 ms，探针通过独立 F64 参考；完整预测仍以下面的实测为准。

模型、F32 权重/激活、默认对称平均和每层 flush 限制不变，没有新增依赖或外部加速库。缩放、patch/head 投影和预测折叠仍在 CPU。

同机完整 release 对比使用 RADV NAVI31 / gfx1100、48 GiB GPU，EPYC 9334、16 核 cgroup 配额，Rust 1.98.1，fat LTO / native CPU；没有 parity-trace。CPU 测 4/16 线程，GPU 的 CPU 前后处理使用 4 线程。上一版 GPU 为 `57eff188` 的已交付 F32 分块实现，当前版本的推理源文件及 shader SHA 与本地一致，模型 GGUF SHA 为 `7628bcbfe43c8fec82bfbeace0ebbeb7dcd49facec6a785a51f430995d704e10`。

常驻计时覆盖同一个模型的完整预测、CPU 前后处理、GPU 同步与读回；JSON 序列化另计。CLI 包含子进程启动至退出，保留 OS/驱动缓存，不是清空磁盘缓存的冷启动。短/标准/关闭对称平均各三轮、每轮五次常驻预测，轮次交替正反顺序运行 CPU4/CPU16/旧 GPU/新 GPU；其他用例各五次，最大上下文仅一次。每个常驻进程另有一次首次预测。短/标准分别运行五次 CPU4/GPU CLI，其他用例各两次，最大上下文各一次。共 98 个有效进程测量、362 次预测。

完整 CLI 仍有明确限制：短输入、标准单变量、关闭对称平均和 1025 步长预测的 GPU CLI 中位数慢于 CPU4。它们的本轮常驻预测适合复用 GPU 模型，但每次启动新进程的调用仍应评估 CPU。长 horizon 首次需要增长 arena 并重新上传权重。CLI 波动也全部保留：标准 GPU 有 3176.3 ms 样本；长 horizon 两次为 1640.2 / 3724.6 ms，不能据其中位数推断稳定尾延迟。短输入 GPU 的 15 次常驻样本为 22.2–718.2 ms，包含未发现已知任务重叠的 718.2 ms 慢样本，未归因或删除。标准 GPU 常驻范围为 40.8–43.2 ms。Auto 的选择策略不变。

每次测量前等待连续三秒无已知 Rust/C++ 编译/链接及 RMI/GPU probe 任务，测量中继续采样；两次检测到重叠的尝试已重测，原日志保留。中途一次等待空闲超过 600 秒，随后核对相同的二进制/源码哈希并从已接受数据续测。有效样本均未采到这些任务重叠；这仍不能证明独占物理主机或 GPU。最大上下文仅验证本次容量与延迟，不能代表 p95。

全部最终预测通过原有 CPU/GPU 误差界，NAVI31 最差最终 NRMSE 为 `2.5752e-6`；同后端的进程间输出哈希一致，CPU4/CPU16 输出字节一致，进程内重复和对应 CLI 也保持一致。普通用例首次后保持 194 次静态上传；长 horizon 因 arena 增长为 387 次，随后不再重传。默认预测仍有 50 次计算提交，独显 staging 另增加每次预测 10 次边界传输；关闭对称平均减半，长 horizon 加倍。最终 GPU 进程峰值 RSS 为 882.5 MiB，Vulkan 分配计数峰值为 875.2 MiB（包含 staging，并非纯显存驻留量），这两种口径不能直接相加。

全部耗时样本、首次预测、CLI、哈希、计数及数值比较见 [gpu_small_input_optimization.json](gpu_small_input_optimization.json)。复现仍使用 [README](README.md#性能复现) 的 release 构建和 benchmark 入口；分别设置 `--threads 4` / `--threads 16`，以及本节列出的重复次数与模式顺序。内置 `--wait-idle` 默认只检查 Rust 编译器，本次临时 runner 额外检查 C++ 编译器和已知推理客户端。原始输入、预测、stderr、构建日志、硬件和两段 runner 已取回本地 `target/timestral-gpu-small-final-results.tar.gz`，SHA-256 `fdb13ce5553d1818e3bdfeb435060c98a04011952c2069be3934931d623d55f1`。


最新 Oracle 证据见 [gpu_small_input_verification.json](gpu_small_input_verification.json)：M3 Max / MoltenVK 上 10 个用例 × Vulkan/Auto，共 20 次 GPU CLI、6,788 个检查点，沿用原有误差界全部通过。203 个 F32 张量 payload、mask、position、缺失通道以及检查点的顺序/形状/次数按位或精确检查；浮点路径仍要求 `max_abs <= 3e-5 + 3e-4 * max_abs(reference)` 和 `RMSE <= 3e-5 + 5e-5 * RMS(reference)`。

最差最终 NRMSE 为 `3.1853e-6`。长 horizon 大幅值尾部的最大最终绝对误差仍为 `0.07275390625`，中间绝对误差最高 `3136`；这不表示所有绝对误差都小。Vulkan/Auto 的最终输出精确一致，另两次关闭运行时 trace 的普通 CLI 也与对应插桩输出一致。3 个 GPU/打包检查通过，覆盖原始位模式、独立 F64 参考、padding、不完整分块、1/5/19/32/33 行边界及大幅值 F32/BF16；8 个未改动的模型单测和 5 个 Python 检查通过。完整 shader 检查使用与 CI 相同的 glslang 15.1.0；fmt 和 diff 检查通过。

NAVI31 的 release 验证比较最终预测；该设备没有运行官方 Oracle 的全部中间检查点。本轮未重复全库测试、官方数据集质量评测或并发服务吞吐测试。当前性能结论限于下述硬件和合成请求。

## 上一版：复用 F32 分块内核

以下保留上一版实现与采样，其短输入结论不代表上面的当前实现。

Timestral 的投影改用仓库已有的 F32 分块矩阵乘法。模型文件、F32 激活/权重和数值验收阈值均保持原样。GPU 上传时把矩阵存储转为 `[input, output]`，重排复用现有 Rayon 线程池；GPU arena 增长时仍按原逻辑重新上传。每层的 flush 限制保留，没有修改 shader 或引入依赖。

### 定位依据

NAVI31 上使用临时插桩，在每个算子后提交并等待，以同步墙钟时间分组。这些诊断包含额外提交开销，不是 GPU timestamp 或无扰动的逐 kernel 时间线。标准输入两次常驻诊断的矩阵乘法分别为 844.2 / 842.3 ms，占诊断阶段约 96%；4096 点输入为 5639.8 / 5645.1 ms，占约 98%。原 F32 路径每个 64 线程工作组只有一个线程做完整标量归约。

分块内核复用 F32 FMA，不将激活或权重转为 F16/BF16。其归约结果按原有混合绝对/相对误差界验收。权重重排按原始位模式检查，并覆盖不完整分块及非法 shape；GPU 算子检查覆盖 1/5/33 行、130 输入维、65 输出维、输入/输出 padding，并与独立 F64 参考比较。

### 同机 A/B

硬件仍为 RADV NAVI31 / gfx1100、48 GiB 显存，16 核配额的 EPYC 9334；Rust 1.98.1，完整 release/fat LTO/native CPU，无 parity-trace，4 个 CPU 线程。原始版本与优化版在同一机器使用相同模型和输入。最终推理源文件 SHA 与本地一致，GGUF SHA 为 `7628bcbfe43c8fec82bfbeace0ebbeb7dcd49facec6a785a51f430995d704e10`。

常驻计时包括完整预测、CPU 前后处理与 GPU 同步读回；完整 CLI 计入进程启动至退出，保留系统/驱动缓存。主矩阵每次先执行一次首次预测，再重复 3 次常驻预测，另启动 2 次 CLI；最大上下文仅重复 1 次、CLI 1 次。短输入和标准输入另各补 5 次交替 CLI，表中使用全部 7 次的中位数。共 89 个进程测量、155 次预测，不含被丢弃的受干扰尝试和中间顺序重排版本。基线同时测 CPU/Vulkan；最终版本测 Vulkan，CPU 实现未改，输出与同输入的基线 CPU/GPU 都比较。

八组最终预测与基线 CPU/GPU 均通过原有误差界；NAVI31 最差最终 NRMSE 为 `2.5752e-6`。每个后端的重复预测和对应 CLI 输出都精确一致。普通用例首次上传后保持 194 次上传，1025 步因 arena 增长为 387 次，随后不再重传。最终常驻进程峰值 RSS 最高约 887.9 MiB；设备峰值分配最高 820.9 MiB，与原分配策略一致，两者口径不同。

完整采样、二进制/源文件哈希、诊断分组及验收记录见 [gpu_optimization.json](gpu_optimization.json)。复现沿用 [README](README.md#性能复现) 的 release 构建和 benchmark 命令；使用 `--warm-repeats 3 --cli-repeats 2`，最大上下文使用 1/1。原实现使用 `efc1477` 的推理代码；远程基线从 `cc72a61` 构建，两者推理实现相同，前者仅增加性能测量工具。`--wait-idle` 默认只检查 Rust 编译器，重现本次隔离口径时还需检查 C++ 编译器及其他 GPU 客户端。补采样仅针对短/标准输入，以基线/优化版交替运行各 5 次。
