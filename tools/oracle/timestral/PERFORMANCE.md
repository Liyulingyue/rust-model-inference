# Timestral-209M F32 性能验证（2026-10-22）

本次实测应优先使用 CPU。GPU 功能与数值检查通过，但在这台 NAVI31 上，默认行为的常驻预测比四线程 CPU 慢 1.47–5.63 倍；完整 CLI 也更慢。Auto 实际选择 GPU，因此本机性能优先时应显式指定 `--compute cpu`。

原始采样与验收记录见 [performance.json](performance.json)，复现入口见 [README.md](README.md#性能复现)。推理实现没有因本轮性能验证发生修改，也没有改变精度或关闭默认对称平均。

## 环境与测量口径

- 双路 AMD EPYC 9334，128 个可见逻辑 CPU；容器 CPU 配额为 16 核，内存上限 55 GiB。线程未绑定 NUMA 节点。
- 真实硬件 `AMD Radeon Graphics (RADV NAVI31)` / gfx1100，48 GiB VRAM；Mesa RADV 25.2.8，Vulkan loader 1.3.275。每个 GPU 进程的设备日志均确认 NAVI31，未使用枚举出的 llvmpipe 软件设备。
- Rust 1.98.1，`--release --features vulkan`，fat LTO、一个 codegen unit、`target-cpu=native`，无 `parity-trace`。CLI 和常驻模型示例均在远程编译，用时 7m32s。
- 模型为同一份 837,265,632-byte F32 GGUF；SHA-256 `7628bcbfe43c8fec82bfbeace0ebbeb7dcd49facec6a785a51f430995d704e10`。本地和远程模型均位于 `/Users/gouzi/Documents/git/rust-model-inference/models/Timestral-209M/`。
- 主矩阵使用四个 CPU 线程，每个后端一次首次预测、五次常驻重复预测，以及三个独立 CLI 进程。常驻计时包含 CPU 前后处理和 GPU 同步/读回；CLI 覆盖整个子进程生命周期。保留文件及驱动缓存，不能称为磁盘冷启动。
- 全部任务串行，75 个进程测量、168 次预测；每两秒检查编译进程，未观察到编译/链接重叠。另有模型上传任务存在，未独占整台物理主机。受编译干扰的两轮 M3 Max 桌面数据保留在本地 target，未用于本报告结论。

## 延迟

单位均为毫秒，数值为样本中位数。`r` 是联合目标变量数，协变量另列。除显式对照外均保留默认对称平均与裁剪设置。

| 96 → 24，r=1 | 143.6 | 211.6 | 1.47 | 378.9 | 1039.6 |
| 512 → 96，r=1 | 242.4 | 842.4 | 3.48 | 496.7 | 1439.6 |
| 512 → 96，关闭对称平均 | 127.3 | 422.5 | 3.32 | 339.4 | 1010.5 |
| 4096 → 96，r=1 | 1152.9 | 5757.7 | 4.99 | 1352.0 | 6320.4 |
| 512 → 96，r=8 | 1176.9 | 6626.9 | 5.63 | 1426.5 | 7211.7 |
| 512 → 96，1 target + 1 past + 2 known covariates | 1212.8 | 6614.5 | 5.45 | 1417.3 | 7201.6 |
| 512 → 1025，r=1 | 982.7 | 4267.4 | 4.34 | 1173.2 | 5182.3 |
| 32768 → 96，r=1，单次边界检查 | 15891.2 | 44857.5 | 2.82 | 16014.2 | 45562.9 |

最大上下文每个后端只有一次常驻重复样本和一次 CLI 样本，另有一次首次预测；它证明容量与该次延迟，不代表 p95 或稳定的延迟分布。主矩阵的全部样本、首次预测及最小/最大值在 JSON 中。

Auto 的 512 → 96 常驻中位数为 847.3 ms（3 次），完整 CLI 为 1436.5 ms（2 次）；输出与严格 Vulkan 完全一致。首次 GPU 预测仍有初始化成本：短输入第一次为 1746.3 ms，常驻中位数为 211.6 ms；512 点输入为 1478.3 ms / 842.4 ms。该首次成本受驱动缓存影响。

## CPU 线程扩展

常驻中位数，单位毫秒。1/8/16 线程各三次重复样本，四线程使用主矩阵五次样本；各线程数输出精确一致。

| 线程数 | 512 → 96 | 4096 → 96 |
| --- | ---: | ---: |
| 1 | 502.3 | 3417.8 |
| 4 | 242.4 | 1152.9 |
| 8 | 217.1 | 741.7 |
| 16 | 194.0 | 588.7 |

在这个 16 核配额下，常驻预测可以使用 `--compute cpu --threads 16`；相对四线程，标准输入快约 1.25 倍，4096 点输入快约 1.96 倍。线程扩展结果不代表并发请求吞吐。

## 内存、缓存与数值

- 进程峰值 RSS：CPU 最高约 844.1 MiB，GPU 最高约 944.3 MiB。Vulkan 设备累计峰值分配约 772.9–820.9 MiB；RSS 与设备分配不是可直接相加的同一口径。
- 标准输入的全部张量验证约 147–150 ms，模型文件打开小于 0.1 ms，JSON 序列化约 0.05–0.07 ms。短 CLI 的总耗时需要包含这些进程内固定成本。
- 普通 GPU 用例在首次预测后一直保持 194 次静态上传，六次预测没有再次上传权重。1025 步预测首次因 arena 容量增长变为 387 次上传，之后五次重复保持不变。
- 普通默认预测每次有 50 次队列提交；关闭对称平均为 25 次，1025 步预测为 100 次。源码在每层后 flush，单次 Transformer 为 25 次提交。这是可确认的提交次数，未通过 GPU profiler 量化其耗时占比。
- 八组 CPU/GPU 最终输出均满足原有混合误差界；最差最终 NRMSE 为 `3.06e-6`，最大绝对偏差 `1.7548e-4`，均出现在 1025 步预测。最大上下文的最大绝对偏差为 `2.8610e-6`。同一后端的所有重复预测和对应 CLI 输出精确一致，Auto 与 Vulkan、各 CPU 线程数之间也精确一致。

本轮未运行官方数据集质量评测、NAVI31 上的 Oracle 全部中间检查点比较、并发服务吞吐或逐 kernel profiling。GPU 仍是 CPU/GPU 混合入口，输入缩放、patch/head 投影和后处理保留在 CPU；本报告只说明已测硬件与合成输入的端到端性能。
