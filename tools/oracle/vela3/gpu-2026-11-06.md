# Vela3 混合 GPU 路径验证（2026-11-06）

在用户更新后的 `d03b30a6c` 上，三个模型族经共享 `ComputePolicy` 和现有 `PreparedRows` / `Weight` 投影分发接入 Vulkan。保留 `--model <底座> --adapter <Vela 包>`、九个既有 Cargo binary，以及原 `system_one` 的 CPU 语义；新增 `system_one_with_policy`，没有修改共享算子、shader 或依赖。

自动标签定义的 greedy 生成固定使用 CPU，避免生成文本分叉后改写 span 输入。这是线性投影与 CPU 步骤混合执行的路径。attention、delta recurrence、预处理、归一化和解码仍包含 CPU 工作，未实现完整设备常驻图。此前 CPU-only 入口的限制在本次解除；既有 BF16 内部检查失败不因此变为通过。

## 主机、构建与证据

- macOS 27.2 / arm64，Apple M3 Max，64 GiB 内存；Rust 1.98.1，`release-fast`，真实请求使用四线程。
- 物理 GPU 通过 Vulkan / MoltenVK，设备日志为 `Apple M3 Max`。未使用软件 ICD、云 GPU 或 Python 执行 Native 计算。
- 测试子进程设置 `DYLD_LIBRARY_PATH=/opt/homebrew/lib`、`VK_ICD_FILENAMES=/opt/homebrew/etc/vulkan/icd.d/MoltenVK_icd.json`、`RMI_COMPUTE_TRACE=1`，清除 `RMI_SCALAR`、`RMI_PARITY_TRACE`、`RUST_GPU_MIN_OUTPUTS`、`RUST_GPU_MAX_ROWS`。没有修改 shell 配置或安装全局依赖。
- 本地原始日志、响应、比较结果与二进制位于 `.codex/vela3/gpu-20261106/`，不提交大数组或模型。SHA256、命令和计数摘要保存在 [verification.json](verification.json) 的 `gpu_2026_11_06`。
- Fast/lite/vision 全请求使用 `rmi-vulkan`；`rmi-final` 另包含 System One 的 `--gpu` 第二层参数白名单，并实跑 alias 和缺设备分支。最终 `rmi-calibrated` 再将自动定义生成固定在 CPU，未改变这三组请求的计算；mini/turbo 补跑使用该构建。不能把早期构建的命令冒充最终二进制的全量复跑。

## 真实请求对照

所有表内请求都与已有固定官方 Oracle 比较。浮点采用 `abs(actual-reference) <= atol + rtol * abs(reference)`；题目顺序、离散选择、字符串、span 偏移和 usage 精确比较。概率与 GPU 归约不做逐位对齐。

| 请求 | 题数 | CPU 对 Oracle max_abs | Vulkan 对 Oracle max_abs | Vulkan 对当次 CPU max_abs | atol / rtol | GPU 投影数 |
|---|---:|---:|---:|---:|---|---:|
| Fast 全九种 adapter | 18 | `1.749e-6` | `1.172e-6` | `1.001e-6` | `5e-4 / 5e-4` | 5,040 |
| d3-lite choice/noul/score/span | 14 | `0.004634` | `0.008009` | `0.003664` | `0.01 / 0.01` | 2,851 |
| Fast-vision 图文混合 | 9 | `3.353e-7` | `3.576e-7` | `3.576e-7` | `5e-4 / 5e-4` | 4,653 |

三组 CPU 请求的 GPU 投影数均为零；三组 Vulkan 请求的题目顺序与 usage 精确一致，全部响应通过原有误差门槛。Fast-vision 包含图像 decision、halu/OCR/box 以及文本 router/set/span 分流，不将单独视觉子接口当作完整包装器的证据。

Fast 浮点提示词的三问另覆盖 CPU / Auto / Vulkan：Auto 和 Vulkan 各有 672 次 GPU 投影，对 Oracle 最大误差 `7.041e-7`；CPU 为 `1.552e-6`。最终构建的 `--gpu` 也是 672 次投影，响应与显式 Vulkan 完全相同。

投影数统计实际 `scope=linear backend=Vulkan` 日志，不把初始化或 partial warning 当作设备执行。累计提交数比投影数多一次 warmup。Fast 全路由累计上传约 22.0 GB、GPU 峰值分配约 20.8 MB；vision 混合累计上传约 11.7 GB、峰值约 45.2 MB。这些计数说明当前路径有重复上传与读回开销，不能称为权重或激活全程常驻。请求计时受并行编译与系统负载影响，不作为性能基准。

## Mini 自动定义的初始失败

初次 mini 八问请求在 GPU 上执行了 5,364 次投影，全部概率通过原有 `atol=rtol=0.01` 门槛（max_abs `0.011052`，该点仍满足绝对加相对误差界）。完整响应检查仍失败：自动定义从 `text spans that refer to human individuals` 变为 `text spans referring to human individuals`。选择、span 偏移和 usage 均一致，不能因此忽略生成字符串的差别。

随后用当前代码单独运行 CPU 的同一 `ner_auto` 问题，确认原定义精确复现；这不是用户更新后 CPU 基线已有的措辞变化。修复在 `generate_definition_ids` 内使用共享 CPU scope，只固定自动定义生成，返回后恢复请求的 GPU 策略，避免继续修改 span 提示词。初始失败和两段定义原文保留在机器记录中，没有修改比较器或放宽门槛。 修复后的完整八问与官方响应通过，选择、定义、偏移、usage 精确一致；GPU 投影为 2,550 次，对历史完整 CPU 响应 max_abs `0.003370`。本轮当前 CPU 只单独重跑了自动定义问题，未把历史八问 CPU 响应冒充当次整批重跑。

## Mini / Turbo 补充整批检查

最终 `rmi-calibrated` 的两个八问请求均通过原官方 Oracle，题目顺序、离散输出、span 偏移、定义和 usage 精确一致，概率仍使用 `atol=rtol=0.01`。

| 变体 | 题数 | 对 Oracle max_abs | 对历史 CPU max_abs | GPU 投影数 |
|---|---:|---:|---:|---:|
| d3-mini | 8 | `0.011052` | `0.003370` | 2,550 |
| d3-turbo，固定 27B 底座 | 8 | `0.002276` | `0.004649` | 4,900 |

mini 的最大误差对应低置信度点，仍满足绝对加相对误差界。两个整批 CPU 响应来自历史记录；本轮没有重跑它们的完整 CPU 批次，mini 的自动定义问题另有当前 CPU 对照。不能把这两组历史 CPU 比较当作本轮全量 CPU 复跑。Turbo 覆盖四个决策/router 问题及 relation、PII、names-only NER、给定定义 NER，usage 与官方 `510/0` 一致。Turbo 累计上传约 393.2 GB、GPU 峰值约 196.2 MB；同样不代表权重常驻或吞吐基准。

五个已测包的混合 GPU 请求合计 57 问。Flash 共用 d3 投影入口，但缺少本地完整底座，未提供真实 GPU 整模结论。

## 浮点格式、隔离与回退

物理 GPU 测试 `gpu_projection_and_lora_match_cpu_for_all_float_formats` 使用真实共享入口，覆盖 128 行、64 输入维度、128 输出维度、rank 32 的底座 + bias + LoRA。门槛固定为 `atol=rtol=2e-4`。

| 权重格式 | GPU 对 CPU max_abs | 实际提交增量 |
|---|---:|---:|
| F32 | `7.153e-7` | 2 |
| F16 | `0` | 2 |
| BF16 | `1.431e-6` | 2 |

每个格式都在全局 GPU 已启用后进入 CPU scope，确认 CPU 参考没有提交；GPU 计算后再进 CPU scope，参考响应精确复现且提交数不变。小投影仍可按共享门槛走 CPU。

最终构建另外执行三问真实请求：

- 缺失 ICD：Auto 成功，零 GPU 投影，完整响应与 CPU 精确相同；严格 Vulkan 在模型加载前报 `requires a usable Vulkan device`，stdout 为空。
- 未编译 Vulkan feature：Auto 成功，零 GPU 投影，响应与 CPU 精确相同；严格 Vulkan 报 `--features vulkan`，stdout 为空。
- 严格策略在返回响应前还检查共享设备是否因队列故障禁用，避免 legacy 投影在 CPU 上修复后静默返回成功。本轮未注入真实设备故障。

## 复现与边界

Fast、d3-lite 和 Fast-vision 的官方响应按 [README](README.md) 生成，再将 Native CLI 加 `--compute cpu`、`--compute vulkan` 分别保存并用同一比较器和原有门槛比较。Fast 的 `requests/fast-floats.json` 用于三策略、alias 与设备缺失探针；vision 的 `requests/fast-vision-mixed.json` 使用公开包装器 Oracle 生成的 `.request.json`（含图像路径）。完整命令与二进制哈希见机器记录。

本轮未验证 flash 的真实 GPU 整模（本地缺完整底座分片）、d3 图像 GPU、跨厂商/跨主机、长上下文吞吐、完整任务质量基准或完整设备图。没有重跑 mini/flash/turbo 的内部 BF16 激活门槛；原有超限与 d3 图像精度限制保持，不能用响应容差通过替代。Clippy 未重跑。HTTP、GGUF、文本生成和视频不属于这条路径。
