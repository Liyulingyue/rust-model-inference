## 架构注册表

`timestral` 使用独立的 `src/models/timestral/` 配置、张量契约和概率预测图，由主 CLI 的 `--timestral-request` 入口分发，不进入文本模型/Tokenizer 路径。

主模型代码当前认识这些 architecture：`bert`、`qwen2`、`qwen2vl`、`qwen3`、`qwen3vl`、`qwen3vlmoe`、`qwen35`、`edge0`、`qwen3tts`、`llama`、`mistral3`、`gemma2`、`granite`、`hunyuan-dense`、`pig`、`lfm2`、`lfm2moe`、`lfm3`、`nanbeige`、`dory`、`gemma4`、`spark2_5`、`mellum`、`dreamx`、`astronex_world`、`laya`、`arktts`、`hy_v3`、`audio8_asr_infinite`、`funasr-sensevoice-encoder`。其中 `bert` 使用 BERT/XLM-R 文本 embedding 路径；`gemma4`、`spark2_5`、`mellum`、`dreamx`、`astronex_world`、`audio8_asr_infinite` 和 `funasr-sensevoice-encoder` 使用各自的专用配置加载路径；`astronex_world` 通过显式主模型/组件 pair 路由进入视频 CLI，组件文件的 GGUF architecture 仍为 `clip`；`mellum` 有独立的 `src/models/mellum/trunk/`，不复用 qwen3 trunk：它与 qwen3moe 在 tokenizer（`mellum2` vs `qwen2`）、位置编码（仅 7/28 非 SWA 层用 YaRN，SWA 层无缩放）、Attention/KV（21 层滑动窗口 1024）三处不一致，因此不能按“相近模型”路由；MoE 张量命名与 Qwen3 相同但门控后的专家顺序、权重归一和累加顺序按 llama.cpp `build_moe_ffn` 独立实现。`clip` 和 `funasr-sensevoice-encoder` 是 mmproj 组件架构，不是可独立生成的主模型。`mistral` 与 `mistral3` 均复用 llama trunk：`mistral`（1/2 / 7B 等）走 GGUF 的 `llama` arch，文本模板靠 `general.name` 包含 `mistral`/`ministral`/`shieldstral` 触发 `[INST] … [/INST]`；`mistral3` 走 GGUF 的 `mistral3` arch，文本模板同样靠这三个子串之一触发。`shieldstral` 子串匹配是为 `Mistral-Shieldstral-1.0-3B` / `-22B`（Mistral 的内容审核系列）专门加的——它们的 `general.name` 是 "Shieldstral 1.0 3B" / "Shieldstral 22B"，与 "Mistral" / "Ministral" 只共享后缀字面。

服务端只覆盖其中较窄的一组运行模式。具体限制见 [README 的“服务端模式”](README.md#服务端模式)；模型是否出现在本清单，不代表它已经支持服务端流式输出或请求级动态媒体输入。

模型实现对照过的外部仓库、固定提交和 Oracle 入口见 [参考实现与 Oracle 清单](REFERENCE_IMPLEMENTATIONS.md)。

Audio8-TTS-Realistic-Air 使用专用 `arktts` / `arktts_codec` 配对加载路径，必须通过 `--tts`；不进入通用文本或 JEV 后端。用法见 [usage/arktts.md](../usage/arktts.md)。
